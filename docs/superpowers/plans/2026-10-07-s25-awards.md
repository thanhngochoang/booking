> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Awards no longer sit in "Chờ duyệt" because nobody can review them locally: the staff CLI works end to end against the emulators (list, show the proof files, decide) with one command, the seed README walks through approving the seeded pending award, and S25.01 shows the "Đã khai" header exactly as the mock. **Architecture:** No new callable, screen or route. Review stays on the existing `reviewAward` use case (`packages/domain`) driven by the staff CLI `app_flutter/firebase/functions/tools/awards.ts`; the CLI learns an emulator mode (proof files downloaded through the Admin SDK instead of signed URLs, which need a service-account key) and a wrapper script `scripts/awards-local.sh` sets the emulator environment the same way `scripts/backend-local.sh` does. The app change is a copy/layout fix in `MyAwardsScreen`. **Tech Stack:** TypeScript (Functions tools, `node --test` via `tsx`), Bash; Flutter, `flutter_test`. **Spec:** `docs/superpowers/specs/2026-10-05-provider-types-portfolio-jobs-design.md` §2.3 (awards, tier), `docs/superpowers/specs/screens/portfolio-awards.md` (S25.01, S25.02), mock `docs/design/ui-mock.html#S25.01`, main spec `2026-10-01-remaining-screens.md` §2 (S23.07 row: "tạm duyệt bằng CLI"), plan `docs/superpowers/plans/2026-10-05-b1-awards-artist-tier.md` Decision 7 (CLI), `app_flutter/firebase/functions/seed/README.md`. **Issue:** #145

## Decisions

1. **Keep the CLI for phase 1; no staff callable change and no in-app staff screen.** `reviewAward` is already a callable (staff claim `staffRole == 'admin'`) and the CLI already drives the same use case. An in-app staff screen would add a staff-only surface to the consumer app, needs proof viewing (signed URLs) and an audit view, and would be thrown away when S23.07 lands in the web dashboard (phase 1.5, #83). What blocked review was not the missing UI but that the CLI's `show` could not run against the emulators (signing needs a key) and nobody documented a one-command local run; that is what this plan fixes.
2. **Emulator `show` downloads the proof files** to `$TMPDIR/awards/<awardId>/` with the Admin SDK (which bypasses Storage rules on the emulator) and prints the local paths; against a real project it keeps the 15-minute signed URLs. Mode = emulator when `FIREBASE_STORAGE_EMULATOR_HOST` is set.
3. **Bucket on the emulator:** `STORAGE_BUCKET`, else `FIREBASE_STORAGE_BUCKET`, else (only in the wrapper script) `project_info.storage_bucket` of `app_flutter/android/app/google-services.json`, else `<project>.appspot.com`. The app uses the default bucket from its Firebase options, which comes from the same file.
4. **The wrapper refuses real credentials:** `scripts/awards-local.sh` unsets `GOOGLE_APPLICATION_CREDENTIALS` (as `backend-local.sh` does) and the CLI calls `assertLocalEmulators({ allowAnyProject: true })` whenever any of `FIRESTORE_EMULATOR_HOST`, `FIREBASE_AUTH_EMULATOR_HOST`, `FIREBASE_STORAGE_EMULATOR_HOST` is set, so a half-set environment cannot touch a real project.
5. **`list` shows how long each award has waited** (`waiting 3d 4h`), oldest first, so the 3-business-day promise in S25.02 ("Duyệt trong 3 ngày làm việc") can be checked by eye. Pure formatter, unit-tested.
6. **S25.01 header copy (mock wins):** the mock's `.sec` is title "Đã khai" on the left and the count "4 giải" on the right in tertiary ink; the app's single string "Đã khai · {n} giải" is replaced by two keys. The count is not a link (mock `span` without action).

## Review Focus

1. Running the CLI with emulator hosts set but `GOOGLE_APPLICATION_CREDENTIALS` still exported (a developer's shell): it must use the emulators, never the real project. Pinned in Task 1 (`emulator env with a remote host is refused`) and the wrapper's `unset`.
2. `show` on the emulator for an award created in the app (files in Storage): no signing error; files land in `$TMPDIR/awards/<id>/`. Pinned in Task 1 (`emulator show downloads files instead of signing`).
3. `show` for an award whose proof has no files (the seed): prints links only, does not require a bucket. Pinned in Task 1 (`show without files needs no bucket`).
4. After `approve` on the seeded award, Bình's S25.01 flips the row to "Đã duyệt" and the `onAwardWrite` trigger recomputes the tier (1 approved → still Cá nhân, "Còn 2 giải…"). Not testable in this sandbox (needs the running emulators): written as the manual check in the seed README and the ledger.
5. The header at 320 dp and 1.3× text: "Đã khai" and "{n} giải" on one line without overflow. Pinned in Task 2 (existing `fits $width wide at text scale 1.3` loop gains the header assertions).

## Chi phí Google

- Firestore: CLI `list` = 1 query on `awards (status, createdAt)` (index exists), one read per pending award; `show` = 2 reads; a decision = the existing `reviewAward` transaction. These run on the emulators in development; in production a staff member runs them a few times a day: < 1,000 reads/month at (c).
- Storage: emulator downloads cost nothing; production `show` keeps signed URLs (egress = the proof files staff open, ~3 files × ~0.6 MB per award; at 100 awards/month < 0.2 GB → < $0.03).
- Functions, scheduled jobs, paid APIs: none added (`onAwardWrite` and `purgeAwardProofs` already exist).
- App: the header change reads nothing new.
- Conclusion: **+$0/month at (b) 1,000 MAU; +$0.03/month at most at (c) 10,000 MAU** (egress unit price $0.12/GB is "chưa xác nhận" in the cost spec).
