**Goal:** A customer posts a job in two steps (S15.01), follows it from the third tab "Việc đăng" of Đặt lịch (S15.02), compares quotes sorted by fit (S15.03), reads one as a short contract (S15.04) and pays 100% for it ("Chọn và thanh toán" → review → fake payment → S05.02); photographers see matching jobs in a "Việc đang tuyển" tab of Công việc (S16.02), open one (S16.01) and send, edit or withdraw a quote in a sheet (S16.03). Everything runs on the real adapters against the emulators; money uses the existing fake gateway.

**Architecture:** Business rules in `packages/domain` (new `job*.ts`, `quote*.ts` modules with ports and memory stores, like events and albums). Firestore: `jobs/{jobId}` with subcollections `quotes/{photographerId}` (one quote per photographer is a property of the path), `invites/{photographerId}`, `matches/{photographerId}` and `views/{uid}`. Every state change is a callable (`createJob`, `updateJob`, `extendJob`, `closeJob`, `inviteToJob`, `submitQuote`, `withdrawQuote`, `declineQuote`, `acceptQuote`, `openJobInquiry`), a trigger (`onJobQuoteWrite`, `onJobMatchCreated`, `onJobInviteCreated`, `onJobViewCreated`, and the existing `onBookingWrite`) or the existing 15-minute `bookingClock` (job sweeps folded in, no new Scheduler job). `acceptQuote` reserves the quote on the job (30-minute checkout lock), creates a booking draft with `source: 'quote'` and `deposit = price` (100% up front on today's fields), and reuses `createDeposit`; the payment handler moves a quote booking `draft → accepted`; `onBookingWrite` then awards the job, marks the other quotes `not_selected` and withdraws the photographer's other quotes for that day. Quotes, invitations and acceptance all pass the existing `ProviderOrderGate`. The app gets `lib/data/jobs/` (models, Firestore + Functions repository, fakes), five core widgets (`JobCard`, `QuoteCard`, `DeliverableChips`, `FitPill`, `MilestoneTable`), customer screens in `features/jobs/` and photographer screens in `features/job_market/`.

**Tech Stack:** TypeScript (`packages/domain`, Functions v2 callables and Firestore triggers, `node --test`), Firestore/Storage rules and indexes; Flutter, Riverpod 3, go_router, `flutter_test`, fakes in `test/support/`.

## Decisions (where the spec is silent or specs conflict)

1. **100% up front on today's booking fields.** A quote booking is a normal `Booking` with `source: 'quote'`, `jobId`, `quoteId`, `terms`, `deposit = terms.price`, `remaining = 0`. `createDeposit` already charges `booking.deposit`, so the customer pays the full price once; cancellation refunds and the escrow sweep work unchanged on the full amount. The quote booking is a `booking` payment subject (no new subject type). If #129 (plan `2026-10-07-s04-booking-payment.md`) has landed first, use its names per the table "If #129 has landed" in Contract and only add the `source === 'quote'` branch. Ledgered either way.
2. **Escrow release for quote bookings is today's single release** (`bookingClock` step 5) until the two-milestone release of D1 (#129/#130/#134) exists. S15.04, the checkout and S16.03 already show the two-milestone contract (50/50, milestone 2 gets the rounding remainder) because that is what the product sells; the release mechanics come with D1. Deferred, and listed under Needs the owner.
3. **Mock wins on copy, spec on behaviour and codes:** S16.02 tabs "Hôm nay / Việc đang tuyển · {n} / Báo giá của tôi" (mock) instead of "Việc tuyển · {n} / Báo giá" (spec strings); S15.04 milestone 2 "Khi bạn đồng ý ảnh + 48 giờ kiểm tra" / "hoặc tự đồng ý sau 3 ngày" (mock, delivery spec 10-06) instead of "Khi bạn duyệt ảnh"; the S15.04 caption's `source=job` is `source: 'quote'` (`BookingSource` enum, spec 10-05 §4.2); the S16.03 caption "ngày của việc đánh dấu Chờ trên lịch" conflicts with "Báo giá không giữ chỗ" — no availability is written (spec wins on behaviour); the S06.04 calendar marker for quoted days is deferred. `jobs.md` is updated in Task 1.
4. **Flexible jobs: the photographer proposes the day.** A `fixed` job's quote takes the job's day, start and end. A `flexible` job's quote carries `proposal {day, start}` chosen in S16.03 inside `[from, to]` (new field, mock frame `#S16.03-flex`); `end = start + durationMinutes`. S15.03 "Rảnh {date}" shows the proposal day; the booking uses it.
5. **Service area = distance, else city.** `photographers/{uid}.serviceArea` is `{city, radiusKm, center?}`, not a district list. `jobInServiceArea(area, serviceArea)`: with `center`, haversine(area centre, center) ≤ `radiusKm`; without, `cityKeyOf(cityOf(area.name)) === cityKeyOf(serviceArea.city)`. `cityKeyOf` = fold Vietnamese, lower-case, keep `[a-z0-9]` (`"TP.HCM"` → `tphcm`, `"Hà Nội"` → `hanoi`). `cityOf("Quận 1, TP.HCM")` = text after the last `", "`, else the whole name. Dart mirrors `cityKeyOf` with a shared parity table.
6. **Fit is computed on the server.** Spec §5.3 names `RecommendationRepository`, which is on the device (`LocalRecommender`); `job_match` runs on the server and S15.03 must show the same number to the customer. Domain `jobFit(job, provider, day)` (Task 2) is stored on `matches`, `invites` and `quotes` docs; the app never computes it. "Gần tôi" items without a match or invite show no `FitPill`.
7. **Matching at creation.** `createJob` scans ≤ 200 candidates (`photographers where acceptingOrders == true and specialties array-contains specialtyId`), keeps eligible ones (Decision 5, `allowedProviders`, not the customer), reads availability for the best 40 by provisional fit, writes the top 30 `matches/{uid}` in the job's batch, and returns `{jobId, matched}`. `onJobMatchCreated` sends `job_match`. `specialtyId = 'other'` matches nobody (visible in "Gần tôi"). `updateJob` does not re-match.
8. **Visibility rules.** Photographers (role `photographer`) read `jobs` with `status == 'open'`; a photographer who quoted or was invited reads that job in any status. Customers read only their own jobs. Area and type eligibility are enforced on the server at submit/invite; the client list hides ineligible jobs, except "Chỉ Nhiếp ảnh gia" which an `individual` sees dimmed; `studio` never sees "Chỉ Nhiếp ảnh gia" and non-studios never see "Chỉ Studio".
9. **Checkout lock.** `acceptQuote` sets `job.checkout = {quoteId, bookingId, expiresAt = now + DRAFT_EXPIRY_MINUTES}`. While it is active: `submitQuote` (edit) and `withdrawQuote` of that quote and `closeJob` return `conflict`; the expiry sweep skips the job. A new `acceptQuote` (same or another quote) replaces the lock and deletes the previous draft if it is still `draft`. A payment that arrives after the draft was cleaned is refunded 100% by the existing late-payment path.
10. **Award after payment, in the booking trigger.** `handlePaymentNotification` moves a `source: 'quote'` booking `draft → accepted` (no `acceptDeadline`) and the availability day `pending → booked`. `onBookingWrite` sees `draft → accepted` with `source == 'quote'` and runs `awardJobFromBooking` (idempotent; also awards a job the clock expired between the payment and the trigger, since the customer paid inside the lock): job `awarded`, chosen quote `accepted` (+ `bookingId`), other `submitted` quotes `not_selected` (`notSelectedReason: 'awarded'`), matches/invites `jobStatus: 'closed'`, checkout cleared.
11. **Auto-withdraw.** `onBookingWrite`, for any booking that enters `accepted` (from `requested` or `draft`), runs `withdrawQuotesForDay(photographerId, day, exceptJobId)`: the photographer's other `submitted` quotes whose proposal day equals the booking day become `withdrawn` with `autoWithdrawn: true`.
12. **Pending days.** Quoting a day whose availability is `pending` (an unaccepted request) is allowed (S16.01 shows "Bạn có yêu cầu đang chờ"); `booked` or `off` is `day_taken`. `acceptQuote` refuses a day that is `booked`, `off` or `pending` for another booking (`day_taken`).
13. **Notifications emitted here** (table in Contract): `quote_new` (grouped `job:{id}:quotes`), `quote_withdrawn`, `quote_accepted`, `quote_not_selected`, `job_match`, `job_invited`, `job_expiring`, `job_expired`. `job_selected` is not emitted (it would duplicate `quote_accepted`); ledger it for #138.
14. **No new Scheduler job.** `runJobSweeps` (expire, 24-hour notice, reference purge) runs inside `bookingClock` (every 15 min) after the booking sweeps, in its own try/catch. Deadline checks in the use cases do not wait for the sweep (`deadline_passed` as soon as `quoteDeadline <= now`).
15. **Field errors.** `DomainError` gains an optional `field` (`new DomainError('invalid_argument', 'description')`); `toHttpsError` adds `details.field`; the app shows the message under that field. A refusal by the contact filter uses the field name with the suffix `.contact` (`title.contact`, `description.contact`, `message.contact`) so the app can say "Bỏ số điện thoại hoặc link khỏi …" instead of a length message; the app splits the field on `.`. The contact filter is shared with the S27 plan (`2026-10-07-s27-studio-recruiting.md` Decision 11): `packages/domain/src/contact_filter.ts` exports `findContactLeak(text): 'phone' | 'email' | 'link' | 'zalo' | null` — VN phone (9–11 digits allowing spaces, dots, dashes, brackets, optional `+84`/`84`/`0` prefix), e-mail, links (`http(s)://`, `www.`, `word.tld` for `vn|com|me|net|org|io|link|ly`, plus `zalo.me`, `fb.com`, `facebook.com`, `m.me`, `t.me`) and the word "zalo" in any case. Whichever plan lands first creates the module with exactly this signature; the other reuses it and ledgers. Jobs refuse any non-null result with `invalid_argument` + `<field>.contact` (spec 10-05 §5.3), not S27's `contact_in_text`.
16. **Job inquiries.** `openJobInquiry({jobId, photographerId?})`: the owner passes `photographerId` (a photographer who quoted or was invited or matched), a photographer passes none (customer = job owner). The pair chat (`chatIdFor`) is created as `inquiry` if missing and gets `jobId` (latest job context). `Chat` gains `startedBy: 'customer' | 'photographer'` (missing = `customer`), `customerRepliedAt`, `photographerMessagesBeforeReply`; a photographer who started an inquiry may send 3 messages before the customer replies (symmetric with today's customer rule). No new S07.01 UI (job context chip deferred to #131).
17. **Views.** S16.01 creates `jobs/{id}/views/{uid}` once (`{at}`, rules: own uid, photographer, job open); `onJobViewCreated` increments `viewCount`. Create-only, so a view counts once per photographer.
18. **"{m} mới".** The job doc keeps `newQuoteCount` (incremented by `submitQuote` for a new or resubmitted quote); the owner resets it to 0 from S15.03 with a direct write (rules allow only `newQuoteCount: 0` and `quotesSeenAt == request.time`, like chat members' `unreadCount`).
19. **`quoteCount`** = quotes not withdrawn (submitted, accepted, not_selected, declined): S16.01 "{n} thợ ảnh đã báo giá", S15.02 "Hết hạn · {n} báo giá". S15.03's header counts `submitted` ones. `recentQuoters` (≤ 3 `{photographerId, avatarUrl}`, newest first) feeds the avatar row.

## Review Focus

1. **Paying twice or for the wrong thing.** One job ends with exactly one `accepted` quote; a second checkout replaces the first draft; a payment for a cleaned draft is refunded 100%; the booking price equals the quote price and `deposit == price`. Pinned in Task 3 ("a second checkout replaces the first draft", "payment after the lock expired is refunded in full", "award is idempotent", "deposit equals the quote price") and Task 4 integration "accept, pay, award".
2. **Contact leaks.** No phone, e-mail or link in titles, descriptions or messages; the job doc has no address or phone; a photographer cannot read another photographer's quote; a customer cannot read other customers' jobs. Pinned in Task 2 (`findContactInfo` table), Task 4 rules tests, Task 7 ("the job card never shows a phone or address").
3. **Wrong people quoting.** A provider who does not accept orders, is out of area, or has the wrong type cannot quote or be invited; an individual sees "Chỉ Nhiếp ảnh gia" dimmed with a disabled button. Pinned in Task 2 ("invite refuses a closed provider with not_accepting_orders"), Task 3 ("submit refuses …"), Task 9 ("artist-only job is dimmed for an individual").
4. **Double booking.** Quoting a booked/off day is `day_taken`; accepting another booking withdraws the photographer's quotes for that day and tells the customers; accepting a quote whose day became pending for someone else is `day_taken`. Pinned in Task 3 ("auto-withdraw on accepted booking", "accept refuses a day pending for another booking").

// job_eligibility.ts — Decision 6; inputs clamped to 0..1, result an integer 0..100
export function jobFit(job: JobRecord, p: ProviderProfile, day: 'free' | 'pending' | 'busy'): number {
  const spec = p.specialties[0] === job.specialtyId ? 1 : p.specialties.includes(job.specialtyId) ? 0.8 : 0;
  const area = p.serviceArea?.center
    ? Math.max(0, 1 - distanceKm(job.area, p.serviceArea.center) / Math.max(1, p.serviceArea.radiusKm))
    : p.serviceArea && cityKeyOf(p.serviceArea.city) === job.area.cityKey ? 0.6 : 0;
  const budget = !job.budget || p.startingPrice === null ? 0.7
    : p.startingPrice <= job.budget.max ? 1 : Math.max(0, 1 - (p.startingPrice - job.budget.max) / job.budget.max);
  const free = day === 'free' ? 1 : day === 'pending' ? 0.5 : 0;
  const rating = p.reviewCount > 0 ? clamp01((p.ratingAvg - 3) / 2) : 0.5;
  const quality = 0.5 * clamp01(p.completedCount / 20) + 0.5 * rating;
  return Math.round(100 * (0.35 * spec + 0.2 * area + 0.2 * free + 0.15 * budget + 0.1 * quality));
}

// contact_filter.ts — Decision 15 (shared with S27). Money like "1.000.000.000₫" is removed first so
// prices never read as phone numbers; digits may be split by spaces, dots, dashes or brackets.
const MONEY = /\d{1,3}(?:[.,]\d{3})+\s*(?:₫|đ|vnđ|vnd)/gi;
const PHONE = /(?:\+?84|0)(?:[\s.\-()]*\d){8,10}(?!\d)/;
const LONG_DIGITS = /(?:\d[\s.\-()]*){9,}/;
const EMAIL = /[^\s@]+@[^\s@]+\.[a-z]{2,}/i;
const LINK = /(https?:\/\/|www\.|\b(?:zalo\.me|fb\.com|facebook\.com|m\.me|t\.me)\b|\b[a-z0-9-]+\.(?:vn|com|me|net|org|io|link|ly)\b)/i;
const ZALO = /\bzalo\b/i;
export function findContactLeak(text: string): 'phone' | 'email' | 'link' | 'zalo' | null {
  const t = text.replace(MONEY, ' ');
  if (EMAIL.test(t)) return 'email';
  if (LINK.test(t)) return 'link';
  if (PHONE.test(t) || LONG_DIGITS.test(t)) return 'phone';
  if (ZALO.test(t)) return 'zalo';
  return null;
}

export async function acceptQuote(deps: JobDeps, booking: BookingDeps, uid: string, raw: unknown) {
  const input = validateAcceptInput(raw);                       // place.name 3–120 (field 'place'), note ≤ 300, provider ∈ PAYMENT_PROVIDERS
  const now = deps.clock.now();
  await requireCustomerPhone(deps.contacts, uid);
  if (!(await deps.providers.acceptsOrders(input.photographerId))) throw new DomainError('not_accepting_orders');
  const bookingId = booking.ids.newId();
  // 1. Reserve the quote on the job (replaces any earlier lock).
  const { job, quote, previous } = await deps.jobs.runTransaction(async (tx) => {
    const job = await tx.getJob(input.jobId);
    if (!job) throw new DomainError('not_found');
    if (job.customerId !== uid) throw new DomainError('permission_denied');
    if (job.status !== 'open') throw new DomainError('conflict');
    if (deadlinePassed(job, now) && !checkoutActive(job, now)) throw new DomainError('deadline_passed');
    const quote = await tx.getQuote(job.id, input.photographerId);
    if (!quote || quote.status !== 'submitted') throw new DomainError('conflict');
    const previous = checkoutActive(job, now) ? job.checkout : null;
    tx.putJob({ ...job, checkout: { quoteId: quote.id, bookingId, expiresAt: addMinutes(now, DRAFT_EXPIRY_MINUTES) },
      version: job.version + 1, updatedAt: now });
    return { job, quote, previous };
  });
  try {
    // 2. Booking draft at 100% (Decision 1); deletes `previous.bookingId` if it is still a draft.
    await createQuoteBookingDraft(booking, { bookingId, job, quote, customerId: uid, place: input.place, note: input.note,
      replaceDraftId: previous?.bookingId ?? null });            // day booked/off/pending-by-other → day_taken
    // 3. Payment intent: existing use case, amount = booking.deposit = terms.price.
    const intent = await createDeposit(booking, { bookingId, customerId: uid, provider: input.provider });
    return { bookingId, paymentId: intent.paymentId, payUrl: intent.payUrl };
  } catch (e) {
    await releaseCheckout(deps, job.id, bookingId);              // clears the lock only if it still names bookingId
    throw e;
  }
}
