**Goal:** Photographers and staff (`admin`/`sales`) create group photo events in two steps; everyone browses and opens them; customers register (free events now, paid tickets last, money held in escrow until the event is completed), keep a QR ticket in the Đặt lịch tab, and hosts check people in; each event has a hashtag timeline and a members-only group chat.

**Architecture:** All event state is written by Cloud Functions whose rules live in `packages/domain` (new `event*.ts` modules with ports and in-memory stores, like albums and awards). Firestore: `events/{id}` (+ `registrations/{id}` with a `private/contact` snapshot, `timeline/{postId}`), `event_hashtags/{key}`, `ticket_codes/{code}`, the group chat `chats/event_{id}` (+ `pins/`). Clients only read; every write is a callable, a trigger (`onPostCreated` links hashtags, `onRegistrationWrite` syncs chat membership) or the scheduled `eventClock`. Paid tickets reuse the booking payment port (fake gateway), `payments`/`refunds`/`ledger_entries`, and the existing `bookingClock` escrow release (step 5) through `releaseAfter`. The app gets `lib/data/events/` repositories (Firestore + fakes), a Firestore `NearbyEventsRepository` for Explore, and feature folders `features/events/` (S11.01–S11.05), `features/event_chat/` (S11.06), `features/event_create/` (S12.01–S12.02), `features/event_manage/` (S12.03).

**Tech Stack:** TypeScript (domain, Functions v2: callables, `onDocumentCreated`, `onDocumentWritten`, `onSchedule`), Firestore/Storage rules and indexes; Flutter, Riverpod 3, go_router, `qr_flutter` (existing), `mobile_scanner` (new), existing core widgets.

Staff create **platform-hosted** events only in this plan; "tạo hộ" a photographer (`hostConsent`, question 17) is deferred and listed under Needs the owner. `hostConsent` is written as `not_required`.
2. **Managers.** `isEventManager(event, caller)` = host photographer (`host.type == 'photographer' && host.id == uid`) ∨ `staffRole == 'admin'` ∨ (`staffRole == 'sales'` ∧ `createdBy == uid`). Managers cannot register for their own event (`permission_denied`).
3. **Firestore layout** (camelCase per spec §3.3; the relational DDL stays the migration target):

   - `events/{id}/registrations/{regId}` (`regId` ULID): `id`, `eventId`, `userId`, `userName`, `userAvatarUrl`, `quantity`, `amount`, `status`, `holdExpiresAt`, `ticketCode`, `paymentId`, `checkedInAt`, `cancelledAt`, `refundPercent`, `event: {title, type, startAt, endAt, locationName, lat, lng, coverUrl}` (snapshot for S11.04), `version`, `createdAt`, `updatedAt`. Phone lives only in `registrations/{regId}/private/contact` `{name, phone, allowZalo, allowWhatsApp}` (invariant 10).

4. **Callables** (`asia-southeast1`, thin; rules in the domain): `saveEventDraft({eventId?, …fields})` → `{eventId, hashtag}`; `publishEvent({eventId})`; `updateEvent({eventId, …})` (after publish: description, cover, location, capacity up or down to ≥ sold, hashtag while unlocked; dates only while nobody registered — moves the availability day); `cancelEvent({eventId})`; `registerEvent({eventId, quantity, name, provider?})`; `cancelRegistration({eventId, registrationId})`; `checkInRegistration({eventId, ticketCode})` → `{name, quantity}`. Task 7 adds `shareEventPost`, `moderateEventTimeline`, `sendEventMessage`, `moderateEventChat`, `postEventAnnouncement`; Task 9 adds `confirmFakeTicketPayment`, `checkTicketPayment`. The app edits **drafts** only (S12.01/S12.02 resume); post-publish edit UI is deferred (ledger), the callable exists.
5. **Draft lifecycle.** S12.01 "Tiếp tục" calls `saveEventDraft` (creates the draft with title, type, description, cover; the hashtag is reserved then). S12.02 "Lưu nháp" calls `saveEventDraft`; "Đăng sự kiện" calls `saveEventDraft` then `publishEvent`. Locally the form is kept in SharedPreferences `eventDraft:<uid>` on every change (like `postDraft:<uid>`); a server draft id is part of it.
6. **Field rules** (domain `validateEventFields`, partial for drafts, complete for publish): `title` 1–80 after trim; `description` ≤ 1000; `type` ∈ `EventType`; cover required at publish (`coverUrl` under `storageUrlPrefixes()` and `coverPath` `eventCovers/{createdBy}/{eventId}/…`); start and end on the **same VN calendar day**, `endAt > startAt`, `startAt ≥ now + 2 h` at publish; `capacity` integer 1–500; `price` integer 0–100.000.000 and a multiple of 1.000; `registrationDeadline ≤ startAt`, default `startAt − 12 h` when that is ≥ now + 1 h, else `startAt`; `location.name` 1–120, `meetingPoint` ≤ 120, `lat/lng` valid; `hashtag` per Decision 7.
7. **Hashtag.** Generated at the first save: fold Vietnamese to ASCII (`NFD`, drop marks, `đ→d`, `Đ→D`), PascalCase the words, keep `[A-Za-z0-9]`, cut to 36 characters, append `MMDD` of the start day (`PhotoWalkPhoCo1020`; before a date exists, `MMDD` of today). Taken key → append `2`, `3`, … (still ≤ 40). Uniqueness through `event_hashtags/{key}` created in the same transaction; an edit moves the guard. Locked (`conflict`) once `registeredCount + heldCount > 0`, any registration ever existed (`hashtagLocked: true` set by the first registration), or `postCount > 0`.
8. **Ticket code** `VE-XXXX-MMDD`: 4 characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no `0/O/1/I`) and `MMDD` of the event day (VN). Reserved at registration creation in `ticket_codes/{code}`; up to 5 candidate codes are read before any write; all taken → retry the transaction. Shown only for `paid` registrations.
9. **Registration.** One active (`held`/`paid`) registration per user per event (`ux_event_regs_active`); a second call returns the active one (idempotent tap). `quantity` integer: < 1 → `invalid_argument`, > 4 → `limit_exceeded`, > seats left → `sold_out`. `name` 1–60 (prefilled from the profile). `phone_required` for **every** registration including free ones (§3b.1 "booking hoặc vé sự kiện"); the phone and channel permissions are copied from `users/{uid}/private/contact` into `private/contact`. Free: created as `paid` at once with `amount 0`, `registeredCount += quantity`. Paid (Task 9): `held` for 10 min, `heldCount += quantity`. Status becomes `full` when `registeredCount + heldCount == capacity`, back to `open` when seats return before the deadline.
10. **Contact unlock follows status `paid`.** Free registrations are `paid` (spec §3.4), so they unlock the host's external channels (`ticketContactUnlocked`) and let the host read the attendee's phone. This is the spec as written; confirm under Needs the owner.
11. **Attendee cancellation** (`cancelRegistration`): only before `startAt`; `held` → `cancelled` (seats back); free `paid` → `cancelled`; paid `paid` ≥ 48 h before `startAt` → refund 100% → `refunded` (Task 9); paid `paid` < 48 h → `cancelled`, `refundPercent 0`, seat back, money stays held and is released to the host with the other tickets (same as late booking cancellations, §3g.2 row 2). A checked-in ticket cannot be cancelled (`conflict`).
12. **Event cancellation** (`cancelEvent`): managers, status `draft|open|full|closed`, before `endAt`; sets `cancelled`, deletes the host's availability record for the day (only if it holds this `eventId`), marks every `held`/free `paid` registration `cancelled`; each paid ticket is refunded 100% in its own transaction after the event write (Task 9; the clock retries leftovers, so a crash midway never strands money). The S12.03 sheet states the ticket count and refund total.
13. **Check-in** (`checkInRegistration`): managers; `ticket_codes/{code}` → registration of **this** event with status `paid` → sets `checkedInAt`. Unknown code, other event or not paid → `not_found` ("Vé không hợp lệ"); already checked in → `conflict` ("Vé đã dùng"); outside the window (event day 00:00 VN → `endAt + 2 h`) → `not_eligible`. Idempotency: a repeated scan returns `conflict` and never changes counts.
14. **Availability.** `publishEvent` writes `availability/{hostId}/days/{dayKey}` `{state: 'booked', eventId, updatedAt}`; refused with `day_taken` when a `booked` or `pending` record exists; an `off` record is replaced (the host chose to work that day); platform events skip it. Cancel frees the day. S06.04 already links event days to S12.03.
15. **Clock.** `eventClock` (every 5 minutes, Asia/Ho_Chi_Minh): `open|full` past `registrationDeadline` → `closed`; `open|full|closed` past `endAt` → `completed` (+ `completedAt`; group chat `readOnlyAt = completedAt + 7 d`; Task 9: `releaseAfter = endAt + DISPUTE_WINDOW_HOURS` on each held ticket payment); `cancelled` events with paid tickets not yet refunded → refund them (Task 9). Task 9 adds `releaseEventHolds` every 1 minute; `registerEvent` also expires stale holds of the same event inside its transaction, so a late cron never shows a false "Hết chỗ".

The hard part is `registerEvent`: every read before the first write (Firestore transactions; the memory store enforces it), stale holds released in the same transaction (sample):

```ts
return deps.events.runTransaction(async (tx) => {
  const ev = await tx.getEvent(input.eventId);
  if (!ev || ev.status === 'draft') throw new DomainError('not_found');
  if (isEventManager(ev, caller)) throw new DomainError('permission_denied');
  if (ev.status === 'cancelled' || ev.status === 'completed' || ev.status === 'closed'
      || now.getTime() >= ev.registrationDeadline!.getTime()) throw new DomainError('deadline_passed');
  const active = await tx.activeRegistrationOf(ev.id, caller.uid);
  if (active) return resultOf(active);                       // idempotent second tap, no writes
  if ((ev.price ?? 0) > 0) throw new DomainError('not_eligible');   // Decision 27; Task 9 replaces
  const stale = await tx.expiredHolds(ev.id, now);
  const codes = ticketCodeCandidates(dayOf(ev), deps.random, 5);
  const taken = await Promise.all(codes.map((c) => tx.ticketCodeTaken(c)));
  const code = codes.find((_, i) => !taken[i]);
  if (!code) throw new RetryableConflict();                  // the adapter retries the transaction
  // ---- writes from here ----
  let held = ev.heldCount;
  for (const r of stale) { tx.putRegistration({ ...r, status: 'cancelled', cancelledAt: now, updatedAt: now, version: r.version + 1 }); held -= r.quantity; }
  if (ev.capacity! - ev.registeredCount - held < input.quantity) {
    if (stale.length) tx.putEvent({ ...ev, heldCount: held, status: statusAfterSeats({ ...ev, heldCount: held }, now), version: ev.version + 1, updatedAt: now });
    throw new DomainError('sold_out');                       // NB: a throw aborts the tx; see note
  }
  ...
});
```

match /events/{eventId} {
  allow get: if signedIn() && (resource.data.status != 'draft' || eventManager(resource.data));
  allow list: if signedIn() && (resource.data.status in ['open', 'full', 'closed', 'completed', 'cancelled']
                                || resource.data.createdBy == request.auth.uid);

    allow write: if false;
    match /private/{docId} {
